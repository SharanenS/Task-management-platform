## Implementation

Project-work owns update requests, internal meetings/check-ins, historical
recipient snapshots and appended follow-ups in its existing database. No new
service, public port, dependency, queue, external calendar integration or calling
feature was introduced. Current MANAGER ownership or ADMIN authority is checked
independently in the gateway and private service; recipients require an active
project appointment plus current active EMPLOYEE account/profile eligibility.
Ownership is reloaded after waiting for the transaction lock. Project leadership
does not confer a second company role or access to unrelated project information.

The typed GraphQL operations feed manager/admin project coordination pages linked
from project details. The command route requires the current server session and
exact same-origin POST. Request confirmation, strict bounded input, unique intent
identifiers, payload fingerprints and expected follow-up versions protect writes.
Requests and original deadlines remain unchanged when follow-ups are appended.
Downgrade refuses to discard retained coordination records.

No response is faked in production. Pending/NOT_REQUIRED acknowledgement states
reflect the absence of recorded employee responses. The tested future response
payload contract is not an employee response endpoint. Reminders remain manual;
automated intervals/escalation rules have not been approved. See
[s9-coordination-contract.md](s9-coordination-contract.md).

  UTC helper already returns text. The new code was corrected and retested.
- Restricted-runner mock HTTP restrictions caused backend stalls and six OIDC
  unit failures. The same unchanged authentication assertions passed when the
  mock servers were accessible. No production authentication change was made.
- Frontend lint/type checks caught redundant effect state and an unsafe form

- The first credentialed desktop attempt failed before either disposable identity
  was recorded; the original reporter omitted its underlying setup error. A
  separate desktop attempt timed out. Neither is counted as acceptance, and no
  unsupported root cause is claimed for those initial opaque attempts.
- The first tablet compound journey timed out at the final responsive navigation.
  Its sanitized artifact records `page.reload: net::ERR_ABORTED; maybe frame was
  detached?`. Added setup diagnostics and boundary checkpoints retain future
  failure locations without credentials or raw addresses. The compound journey
  was separated into four focused serial cases, with shared cleanup in afterAll.
  All original assertions remain, and no timeout was raised. Desktop/tablet/mobile
  then passed all four cases against the final hardened backend.
- The retained calendar journey timed out at its non-admin authorization matrix;
  its sanitized diagnostic records `apiResponse.json: Response has been disposed`.
  All owned rows and identities were cleaned, and the actual calendar was verified
  unchanged. Publication/history/calculation and the three-role/origin matrix are
  now two independent cases, with every original assertion preserved. Both passed
  at the unchanged 45-second limit. The calendar focus now requires two passes;
  full isolated lifecycle scope therefore increases to 19. Failure diagnostics use
  unique filenames so one case cannot overwrite the other's evidence.
- One concurrent lint attempt encountered Playwright resetting `test-results`
  during its directory scan. Sequential final lint/format/type checks passed; no
  application or lint rule was relaxed to bypass this tooling race.
- Review found that an ORM-loaded project could retain old ownership while a
  transaction waited for its lock. Expiring loaded state after lock acquisition
  closes that edge case; a regression proves the old owner cannot commit.
